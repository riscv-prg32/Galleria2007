# Publishing on the PRG32 Cartridge Store

Release 0.1.0 ships two Store bundles, one per language edition:

| Bundle | Store id | Contents |
|---|---|---|
| `dist/galleria2007-it-0.1.0-store.zip` | `org.riscv-prg32.galleria2007` | `manifest.json`, `icon.png`, `splash.png`, `galleria2007-it-esp32c6.prg32`, `galleria2007-it-qemu.prg32` |
| `dist/galleria2007-en-0.1.0-store.zip` | `org.riscv-prg32.galleria2007.en` | same layout, English edition |

Both were validated with CartridgeStore's own ingestion code
(`_prepare_bundle()`, the implementation of `POST /api/publish/bundle`) and
are **ready for submission**. Checksums are in `dist/SHA256SUMS`.

## Bundle format (CartridgeStore `docs/api.md`, "Bundle Publish")

```text
manifest.json     prg32-metadata-1.0 object + assets + architectures + colophon
icon.png          64x64 palettised PNG (592 bytes)
splash.png        320x200 real gameplay screenshot (the Store's screenshot slot)
*.prg32           one file per architecture: esp32c6 and qemu
```

The manifest is generated by `scripts/pack-store-bundle.sh` from
`metadata/metadata.<lang>.json` and `metadata/colophon.<lang>.json`:

- `abi` **must** be `prg32-metadata-1.0` (the Store rejects anything else);
- `runtime` is removed (the Store writes `runtime.architecture` per variant);
- `assets` = `{"icon": "icon.png", "splash": "splash.png"}`;
- `architectures` = `esp32c6` and `qemu` files;
- `colophon` is embedded as an object.

The Store rebuilds every cartridge from the manifest, icon, splash and
colophon. The rebuilt images are about 53 KB, within the 64 KiB package
limit (≈12 KB free).

## Before submitting

- [ ] `tests/run_tests.sh` — all suites pass
- [ ] `scripts/build.sh` — four cartridges, three budgets respected, position independence proven
- [ ] `scripts/check_hosts.sh` — PRG32-QT, PRG32-iOS and QEMU pass
- [ ] `scripts/pack-store-bundle.sh` — both bundles `READY for submission (store-ingest)`
- [ ] `cd dist && shasum -a 256 -c SHA256SUMS`
- [ ] hardware acceptance on an ESP32-C6 recorded in [acceptance.md](acceptance.md) (frame rate, stereo, two-board multiplayer)
- [ ] metadata reviewed by the project owner: Store ids, license, homepage, wording about the Galleria Borbonica ([provisional.md](provisional.md))
- [ ] human approval of the release

## Submitting (authenticated, human-controlled)

Publishing is never automated by this repository and no credentials are
stored in it. A maintainer with a Store account creates a personal Bearer
token in the Store (`/auth/tokens`) and submits each bundle:

```bash
cd ../PRG32
python3 -m prg32 store publish-bundle ../Galleria2007/dist/galleria2007-it-0.1.0-store.zip \
  --store-url https://store.prg32.uniparthenope.it/ --token "$PRG32_STORE_TOKEN"
python3 -m prg32 store publish-bundle ../Galleria2007/dist/galleria2007-en-0.1.0-store.zip \
  --store-url https://store.prg32.uniparthenope.it/ --token "$PRG32_STORE_TOKEN"
```

or with curl:

```bash
curl -X POST https://store.prg32.uniparthenope.it/api/publish/bundle \
  -H "Authorization: Bearer $PRG32_STORE_TOKEN" \
  -F bundle=@dist/galleria2007-it-0.1.0-store.zip
```

The Store answers `{"status": "pending", "review_required": true, ...}`.
The cartridges appear in the catalog only after an editor verifies the
submission in `/editor/submissions`. Editors may adjust descriptive fields
(title, summary, description).

## After publication

The published variants download to:

- ESP32-C6 boards (setup → Cartridge Store) — the `esp32c6` file;
- QEMU — the `qemu` file;
- PRG32-QT and PRG32-iOS — they accept either portable variant
  ([portability.md](portability.md)).

Mixed-language groups play together: both editions use the multiplayer
signature `galleria2007-v1`.

## Releasing a new version

1. Bump `version` and `updated_at` in every `metadata/metadata.*.json` and
   `metadata/colophon.*.json` (and `CHANGELOG.md`).
2. Re-run the whole checklist above; new bundles are named after the version.
3. Submit as above; the Store keeps versions side by side under the same id.
